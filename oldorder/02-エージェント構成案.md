# 想定エージェント構成

## 結論：段階導入で 4体 → 9体 → 13体

一気に13体作ると運用が破綻する。**まず4体で週次サイクルを回し、データが揃うごとに増やす。**

| フェーズ | 体数 | 導入条件 | 到達状態 |
|---|---|---|---|
| Phase 1 | **4体** | 今すぐ（データ0でも開始可） | 週次MTGが回り、施策が出続ける |
| Phase 2 | **9体**（+5） | Tier 1データが揃ったら | 店舗別の個別最適化ができる |
| Phase 3 | **13体**（+4） | 運用が定着したら（3ヶ月後目安） | 在庫・人材・ナレッジまで自動化 |

---

## Phase 1 ─ 最小構成 4体（今週から）

### 1. 分析エージェント `analyst`
- 売上を 入店客数 × 買上率 × 客単価 に分解し、**どこが崩れたかだけを言う**
- 店舗間比較（坪効率・人時売上高で正規化）、前年比、異常値検知
- 週次ダッシュボードの自動生成
- 禁止事項：施策を提案しない（分析と立案を混ぜると分析が結論に引っ張られる）

### 2. 施策立案エージェント `strategist`
- 分析結果を受けて施策を**3案に絞って**出す。各案に必ず：
  想定効果（金額）/ コスト / 必要リードタイム / 測定方法 / 担当
- 測定方法が書けない施策は却下する（検証できない施策は資産にならない）
- 11月キャンペーン（周年2本＋BF）のような**複数店横断の設計**もここ

### 3. 制作エージェント `creative`
- 店舗の細々したものを量産する担当：
  - 店頭POP・値札・プライスカード・ブラックボード文言
  - Instagram / TikTok 投稿文・ストーリーズ文言・ハッシュタグ
  - スタッフ向け1枚資料（新商品の売り方・接客スクリプト）
  - ノベルティ文言、DM・LINE配信文、館提出用の販促申請文
  - 周年キャンペーンのビジュアル指示書
- Adobe Express 連携でビジュアルまで出せる

### 4. MTG運営エージェント `facilitator`
- 週次MTGのアジェンダを事前生成（前週アクションの進捗つき）
- 議事録 → 決定事項 → タスク（担当・期限）に自動変換
- **前週のアクションが未完了なら必ず冒頭に出す**（やりっぱなしを防ぐ最重要機能）

## Phase 2 ─ +5体（計9体）

### 5〜8. 店舗別エージェント ×4
`store-osaka` / `store-nagoya-parco` / `store-harajuku` / `store-urahara`

各店の文脈を保持させる：立地・客層・坪数・スタッフ構成・館ルール・競合・過去施策の履歴。
全社施策を**その店の事情に翻訳する**のが仕事。

- `store-nagoya-parco`: 館の販促カレンダー・申請締切・館内シェアを常時把握
- `store-urahara`: 成熟店。リピーター/F2転換に特化
- `store-harajuku`: 立ち上げ期。新規獲得と認知に特化
- `store-osaka`: 定着期＋インバウンド（免税）

※4店舗 = 4体にするのは、**店ごとに前提が違いすぎて1体で持つと混ざる**ため。
　実際に数字の出方が全く違う（フェーズ差が最大14ヶ月ある）。

### 9. SNS集客エージェント `sns`
- **既存の SNS Analyzer（このリポジトリ）と直結する担当**
- TikTok/Instagram のトレンド発掘 → 投稿企画 → 効果測定
- SNS → 来店の計測設計（合言葉・限定クーポン）
- ブランド全体 + 店舗アカウントの運用設計

## Phase 3 ─ +4体（計13体）

### 10. 在庫・MDエージェント `inventory`
消化率管理、**店間移動の提案**（コストゼロで売上が立つ最速の手）、値下げタイミング、発注提案

### 11. 人材・育成エージェント `people`
スタッフ別実績分析、売れるスタッフの接客の言語化と横展開、ロープレ台本、シフト最適化（人時売上高ベース）

### 12. 検証・ナレッジエージェント `reviewer`
打った施策の事後検証、**施策DBへの蓄積**、「同じ失敗を繰り返さない」ための番人。
天候・曜日要因を除去して施策の純効果を出す

### 13. 統括エージェント `director`
上記を束ねて、統括（あなた）への報告を1本化。
複数エージェントへの並列指示と結果の統合を担当

---

## 各体がやらないこと（重要）

エージェントを増やすと必ず起きる失敗が「全員が施策を提案し始めて意思決定できなくなる」。
役割の境界を固定する：

| 体 | 出力 | 出してはいけないもの |
|---|---|---|
| analyst | 事実と分解結果のみ | 施策案 |
| strategist | 施策3案（効果・コスト・測定方法つき） | 制作物 |
| creative | 制作物のみ | 施策の是非の判断 |
| facilitator | アジェンダ・議事録・タスク | 施策案 |
| 店舗別 | その店への翻訳と現場制約の指摘 | 全社方針 |
| reviewer | 検証結果と学び | 次の施策案 |

**意思決定するのは統括（あなた）1人。** エージェントは判断材料と実行物を出すだけ。

## 週次の回り方（Phase 1 の運用イメージ）

```
月曜 AM  analyst      → 先週の数字を分解、異常値を特定
月曜 PM  strategist   → 施策3案（うち1つは今週すぐ打てるもの）
火曜     creative     → 採用施策の制作物を一式作る
水〜日                → 現場で実行
日曜     facilitator  → 次回アジェンダ生成（前週アクションの進捗つき）
翌月曜   reviewer*    → 先週施策の検証（*Phase 3から。当面は analyst が兼任）
```
