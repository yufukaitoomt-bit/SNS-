# 現状分析に必要なデータ一覧

優先度を3段階に分けた。**Tier 1 がないと施策は「勘」になる。**
逆に Tier 1 の 1〜3 だけあれば、今週から施策は打てる。

---

## 考え方：売上を分解できる形でもらう

```
売上 = 入店客数 × 買上率 × 客単価
客単価 = 1人あたり点数（セット率） × 平均単価
```

この式のどの項目が落ちているかで打つ手が全く変わる。

| 落ちている項目 | 原因 | 打つ施策 |
|---|---|---|
| 入店客数 | 集客の問題 | SNS・店前・館内導線・看板 |
| 買上率 | 接客/品揃え/価格の問題 | 接客設計・試着誘導・サイズ欠品解消 |
| 1人あたり点数 | 提案不足 | セット提案・コーデ陳列・バンドル |
| 平均単価 | 構成の問題 | 高単価商品の見せ方・値引抑制 |

**だから「売上が下がった」という報告だけでは何もできない。** 分解できるデータが必要。

---

## Tier 1 ─ 必須（これが無いと施策が打てない）

### 1. 日別売上データ（店舗別）★最優先
- **粒度**: 1日 × 1店舗 = 1行
- **期間**: 直近13ヶ月以上（前年同月比のため）。裏原は24ヶ月
- **列**: 日付 / 店舗 / 売上(税抜) / 客数(レシート枚数) / 販売点数 / 値引額 / 返品額
- **これで出せるもの**: 客単価・セット率・平均単価・曜日別傾向・月次の着地予測
- → `templates/daily_sales.csv`

### 2. 入店客数（ドアカウント）★切り分けの要
- **無い場合は「カウンター設置」を即提案事項にしたい**
- これが無いと、売上減が「客が来なかった」のか「来たけど売れなかった」のか**永久に切り分けられない**
- 代替案（カウンターが無い間）: スタッフが30分ごとに手計測、または館の入館者数で代用（PARCOは取得可能）
- **これ1つで施策の的中率が倍変わる。** 優先投資したい

### 3. 時間帯別の売上・客数
- **粒度**: 1時間単位 × 1日 × 1店舗
- **これで出せるもの**: シフト最適化（人時売上高）、イベント開催時間の根拠、閑散時間の施策
- 例：14-16時が死んでいるなら、そこに「限定ドロップ」や「来店特典」を置く

### 4. 商品別（SKU別）販売実績
- **粒度**: 月 × 店舗 × 品番 × 色 × サイズ
- **列**: 品番 / 品名 / カテゴリ / 色 / サイズ / 上代 / 原価 / 入荷日 / 入荷数 / 販売数 / 販売金額 / 値引額 / 期末在庫
- **これで出せるもの**: 消化率、売れ筋/死に筋、カテゴリ構成、**サイズ欠品による機会損失**
- → `templates/sku_sales.csv`

### 5. 在庫データ（店舗別・SKU別）
- 現在庫 / 入荷履歴 / 店間移動履歴
- **即効性が一番高いのがここ。** 「A店で売れてB店で死んでいる在庫」の移動は、
  コストほぼゼロで売上が立つ。4店舗あるなら必ず起きている

### 6. 店舗マスタ（固定情報・1回もらえば済む）
- 売場坪数 / 営業時間 / 固定費月額（家賃+人件費+館コスト）/ 損益分岐点売上 /
  スタッフ人数（社員・アルバイト）/ 立地区分（路面・館）/ 免税対応有無
- **これで出せるもの**: 坪効率、人時売上高(LSP)、店舗間の公平な比較
- → `templates/store_master.csv`
- ※ 売上の絶対額で4店を比べるのは無意味。**坪効率と人時売上高で比べる**

## Tier 2 ─ 施策の精度を上げる

### 7. スタッフ別販売実績
- 個人売上 / 接客人数 / セット率 / 指名・リピート
- 用途: 売れるスタッフの接客を言語化して横展開（= 最も再現性の高い売上向上策）

### 8. 顧客データ
- 会員数 / 新規・リピート比率 / 購入頻度 / F2転換率（初回→2回目）/ 顧客の居住エリア
- 用途: 裏原（成熟店）はリピーター施策、原宿明治通り（立ち上げ期）は新規獲得施策。**打ち分けの根拠**
- F2転換率は小売で最も効くKPI。初回購入者の2回目来店率が上がれば売上は構造的に伸びる

### 9. SNSデータ（既存の SNS Analyzer と接続できる）
- 店舗/ブランドアカウントのフォロワー推移・リーチ・保存数・プロフィールクリック
- **重要**: SNS → 来店の計測手段。合言葉・限定クーポン・ストーリーズ限定告知などで
  「SNS経由来店数」を数えられる仕組みを作りたい。今は確実に計測できていないはず
- このリポジトリの TikTok/Instagram 分析機能をここに繋げる

### 10. EC売上と店舗の関係
- EC売上推移 / 店舗受取利用 / 同一顧客のEC・店舗併用率 / EC在庫と店舗在庫の分離状況

### 11. 過去施策の記録 ★これが無い会社がほとんど
- いつ / どの店で / 何を / コストいくら / 結果どうだったか
- **無ければ今から記録を始める。** 蓄積が無いと毎回ゼロから考えることになり、
  同じ失敗を繰り返す
- → `templates/initiative_log.csv`

### 12. 館（PARCO）関連データ ※名古屋PARCO専用
- 館全体の入館者数 / 同フロア他店の動向 / 館の販促カレンダー / 館の販促枠の申請締切
- 名古屋PARCOは**館依存度が高い**ので、館のイベントに乗るか外すかで数字が変わる
- 1周年（11/01）が館の販促カレンダーとどう噛むかは今週確認したい

## 最小スタート構成

全部揃うのを待つ必要はない。**以下3つだけで来週のMTGから回せる。**

1. 日別売上（売上・客数・点数） 直近13ヶ月 × 4店
2. SKU別販売実績＋在庫 直近3ヶ月 × 4店
3. 店舗マスタ（坪数・固定費・スタッフ数）

形式は問わない（POSのCSVエクスポート、Excel、スクショでも可）。
整形はこちらで引き受ける。

## 週次MTG用の定型データ（毎週同じ形で出す7項目）

1. 週売上 / 予算対比 / 前年同週比（店舗別）
2. 客数・客単価への分解（どちらで崩れたか）
3. 買上率（入店客数が取れていれば）
4. カテゴリ別売上構成と前週差
5. 売れ筋TOP10 / 在庫滞留TOP10
6. 先週の施策の結果（1施策1行）
7. 今週のアクション（担当・期限つき、**3つまで**）

→ `templates/weekly-mtg-agenda.md`
