# 接客分析アーカイブ

接客1件ごとの記録を蓄積し、**データからマニュアルを作る**ためのリポジトリ。

---

## なぜ記録するのか

1件の接客を振り返るだけなら記憶で足りる。蓄積する目的は別で、

- 「効いた一言」が**何度も効いている**ことを証明する → マニュアルに載せる根拠になる
- 「外した一手」が**同じ型で繰り返されている**ことを発見する → 仕組みで潰す
- 失注理由を数えて、**接客の問題か店舗の問題かを切り分ける**

感覚ではなく件数で語れるようになることが狙い。

## ディレクトリ構成

```
接客分析/
├── README.md                    # このファイル（運用ルール＋インデックス）
├── _TEMPLATE.md                 # 記録テンプレート（コピーして使う）
├── records/                     # 接客記録（1接客 = 1ファイル）
│   └── YYYY-MM-DD_客層_商品.md
└── transcripts/                 # 音声の文字起こし（あれば）
    └── YYYY-MM-DD_音声文字起こし.txt
```

## 記録のルール

### ファイル名
`YYYY-MM-DD_客層_商品.md`
例：`2026-10-12_カップル_SMILE-CHAOS.md`

同日に複数ある場合は末尾に連番 → `2026-10-12_カップル_SMILE-CHAOS_2.md`

### 書く範囲
**接客直後、記憶が新しいうちに。** 完璧に書く必要はない。
最低限これだけあれば後から分析できる：

- 試着の順番（商品・色・サイズ）
- 結果（買ったか／買わなかったか・理由）
- 自分が言った言葉で覚えているもの

### タグ
分岐点には必ずタグを付ける。後で横断検索して集計するため。

| タグ | 対象 |
|---|---|
| `#アプローチ` | 声かけのタイミング・入り方 |
| `#ヒアリング` | 質問・情報収集 |
| `#提案` | コーデ提案・商品説明・訴求 |
| `#試着誘導` | 試着に持ち込む動き |
| `#クロージング` | 決めにいく一手 |
| `#アップセル` | 2点目以降・付属品 |
| `#欠品対応` | 在庫がない時の動き |
| `#次回接点` | 連絡先・再来店の仕掛け |
| `#売場` | ディスプレイ・在庫配置など店舗構造 |

## 現時点で見えている仮説

件数が少ないため「仮説」。同じパターンが3件たまったらマニュアルに昇格させる。

### 仮説① ジャストサイズが出た瞬間が、クロージングの最大圧
サイズが決まった直後は購買意思が最も高い。ここで離席すると意識が「買う/買わない」から「他に何かないか」に移る。
→ **離席はクロージング後。**（根拠：2026-10-12）

### 仮説② アップセルは本体確定前に出すと、本体ごと失う
付属品を取りに行っている間に、本体への集中が切れる。
→ **「ご用意します」を取ってから足す。**（根拠：2026-10-12）

### 仮説③ 欠品は失注理由ではなく、連絡先をもらう正当な理由
「入荷したら一番にご連絡します」は欠品時にだけ自然に使えるカード。
→ **欠品が出たら必ず連絡先を取る。**（根拠：2026-10-12）

### 仮説④ 試着エリア正面のディスプレイは、在庫のある色・サイズにする
欠品カラーを飾ると、お客様の欲求が買えないSKUに逃げる。
→ **ディスプレイは「今日お渡しできる一足」を映す鏡。**（根拠：2026-10-12）
